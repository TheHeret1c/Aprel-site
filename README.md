# Aprel Site — сайт заказа еды для кафе

Дипломный проект (колледж, 2024): сайт для реального кафе с меню, корзиной, личным кабинетом и отправкой заказов напрямую в кассовую систему iiko. На защите работал на собственном домене с HTTPS.

## Возможности

- **Меню из iiko** — номенклатура, цены и модификаторы загружаются из iiko Cloud API, а не заводятся вручную
- **Карточки товаров** с модификаторами, избранное
- **Корзина и оформление заказа** — заказ уходит прямо в iiko: на кассовый терминал (самовывоз) или как доставка
- **Вход по одноразовому коду на email** (MailKit, SMTP)
- **Личный кабинет** — профиль, несколько адресов доставки с выбором на Яндекс Картах, история заказов, отзывы на заказы
- **Оплата** — при получении, наличными или картой

## Стек

| Часть | Технологии |
|---|---|
| Бэкенд | C#, ASP.NET Core 8 MVC |
| База данных | PostgreSQL, Entity Framework Core (code-first, миграции) |
| Интеграции | iiko Cloud API, SMTP (MailKit), Яндекс Карты |
| Фронтенд | Razor Views, jQuery, модальные окна |
| Деплой | Docker Compose, nginx (reverse proxy + TLS) |

## Архитектура

```
Браузер ──HTTPS──► nginx ──► ASP.NET Core MVC ──► PostgreSQL
                                   │
                                   ├──► iiko Cloud API  (меню, заказы, доставки)
                                   └──► SMTP            (коды входа)
```

Токен iiko живёт около часа: приложение запрашивает его по `apiLogin`, хранит в сессии в зашифрованном виде (ASP.NET Data Protection) и обновляет по истечении срока.

## Почему проект не развивается

Сайт запускался на домене для защиты диплома и должен был после доработки уйти в продакшн. Доработку пришлось отложить из-за службы в армии, а после возвращения выяснилось, что доступ к iiko Cloud API для лицензии кафе больше не предоставляется. Без API сайт не может получать меню и отправлять заказы, поэтому проект заморожен.

Задачи кафе сейчас решаются в отдельном проекте — [cafe_aprel_automation](https://github.com/TheHeret1c/cafe_aprel_automation): мобильном приложении, которое не зависит от внешних API.

## Что бы я сделал иначе сегодня

- **Секреты — вне кода.** Ключи и пароли лежали в коде и `docker-compose.yml`. Правильно — `dotnet user-secrets` для разработки и переменные окружения / `.env` (не в git) для продакшна.
- **Не открывать админку базы наружу.** pgAdmin был доступен из интернета. Достаточно SSH-туннеля или VPN.
- **Абстракция над внешним API.** Интерфейс над iiko с mock-реализацией позволил бы разрабатывать и показывать сайт без доступа к API — и проект пережил бы отключение интеграции.
- **Единый стиль интерфейса** — общие шрифты и цвета, заглушки для товаров без фото вместо битых картинок.
- **CI/CD** вместо ручной сборки и копирования `publish/` на сервер.
- **Тесты** хотя бы на логику корзины и формирования заказа.

## Запуск

Нужны .NET 8 SDK, PostgreSQL и `apiLogin` для iiko Cloud API.

```bash
cp .env.example .env        # заполнить пароли и ключи
docker compose up -d
```
